Policy: ADR 0011. Contract: `cryptonite_schemas.profile` (import names, never redefine). Schema: migration 050
(`docs/specs/migration-050.md`; merged before this task starts).

## B. `mandate.py`

1. `MandateStatus` gains `STOPPING`, `STOPPED`.
2. `Mandate` gains every 050 column with the same defaults (types from the contract enums: `markets:
   frozenset[Market]`, `direction`, `style`, `environment`, `notify_level`; `Decimal`/`int` fields as in
   `ProfileFields`). `from_row` reads them with `r.get(...)` and the defaults (older rows/tests keep working).
3. Remove `_perps_only_at_l1`'s level rule. Keep the D2 default (perps enabled without a named maximum → 3x). New
   validator `_markets_consistent`: `markets` is the truth; `allow_perps` is derived — if a caller passes
   `allow_perps=True` and markets lacks PERP, add PERP; then `allow_perps = PERP in markets`. Run `profile_errors`
   (`running=status == ACTIVE`) and raise `ValueError` with the joined codes.
4. `risk_adding_change(old, new)`: keep every existing rule; add `or bool(risk_adding_profile_change(...))` built
   from both mandates' `ProfileFields` and modes (`mode_of_level(autonomy_level)`).
5. `is_perp_instrument(id)` delegates to `profile.market_of(id) is Market.PERP`. Delete `PERPS_AUTONOMY_LEVEL`
   after removing every use (B–F). `LEVEL_NAMES` becomes `{L1: "Ask me", L2: "Veto window", L3: "Fully automatic"}`.

## C. `autonomy.py` (ADR 0011 D2, D3)

- `PROMOTION_CONFIRMED` no longer requires `gate.passed`: it requires TOTP and status ACTIVE/PAUSED, sets any target
  level 1–3 **chosen by the operator** (rename the trigger's semantics in the docstring: "operator sets mode"; keep
  the enum value for the audit trail). `gate` is recorded in the transition detail as the advisory health score.
- `BREACH` and `HALF_DRAWDOWN`: kind `NOOP` (no level change), reason kept → callers still record and alert.
- `HARD_STOP`/`BACKSTOP`: status HALTED, **level and allow_perps unchanged** (050's `chk_ai_mandates_perps_markets`
  requires allow_perps to match markets; the old reset to L1 + allow_perps=False would violate it and fail the halt).
- `OPERATOR_DEMOTE`: any lower level (free, no TOTP), unchanged otherwise.
- `PAUSE`/`RESUME` unchanged except RESUME also accepts from STOPPING (→ ACTIVE, TOTP) — the operator changed their mind.
- Remove every `PERPS_AUTONOMY_LEVEL` use. `evaluate_gate` unchanged (advisory health score).

## D. Orchestrator

- `mandate_monitor.py`: HALF_DRAWDOWN demotion removed (keep the once-per-episode WARNING alert, now
  "drawdown ≥ half the hard stop" with no level change); `propose_promotions` stops proposing (keep computing the
  gate report and store it as the health score where it is stored today, or skip if it only feeds proposals — say which
  in the report). **STOPPING → STOPPED:** each pass, a STOPPING mandate with no open positions and no working
  orders becomes STOPPED via `profile_lifecycle.finish_stop` (releases locks, audit event).
- `mandate_gate.py`: breach still recorded (`record_breach`) and alerted; no level change. Entries require
  `accepts_entries(status)` (ACTIVE); exits continue in every status (D13) — keep today's rule for PAUSED/HALTED and
  add STOPPING.

## E. `mandates.py` (`check_mandate`)

Remove the L1 perps condition: perps allowed when `Market.PERP in mandate.markets`. Add the coin-lock defence: an
ADD_RISK order whose `base_asset` is locked by **another** mandate → new `MandateReject.COIN_LOCKED` (not a breach).
The lock set is passed in by the caller (`mandate_gate` loads `ai_profile_coin_locks` once per check) — the pure
function takes `coin_owner: uuid | None`.

## F. API

- `routes/brain.py`: remove both `PERPS_AUTONOMY_LEVEL` conditions (lines ~533, ~749); the "Allow perps" remedy is
  offered at any level and adds PERP to markets. Brain cards and inbox debates on a coin locked by another mandate
  are refused `COIN_LOCKED` with the holder's name (card dry run and approve).
- `settings_registry.py`: `guard.perps_level` text → "Any execution mode (ADR 0011)", source ADR 0011. New runtime
  settings (also in `runtime_settings.py`): `autotrade.enabled` (0/1, default 0, choices Off/On, enabling is
  risk-adding → TOTP) and `autotrade.max_allocated_pct` (default 90, 10..100, raising is risk-adding).
- `routes/ai.py`: create/patch accept the profile fields (validated by `Mandate`); risk-adding edits need TOTP as
  today; `/autonomy/confirm` lets the operator set the mode directly (TOTP when raising); new
  `POST /mandates/{id}/start`, `/pause` (existing), `/stop` (body `{close: bool}`), all through
  `profile_lifecycle`. Every lifecycle and risk-adding route requires `require_human_operator` (machine token → 403).

## G. `profile_lifecycle.py` (the single lifecycle implementation)

```python
class LifecycleError(Exception): code: str; detail: dict
async def start(conn, mandate_id, *, actor, totp_ok: bool, settings) -> Mandate
async def pause(conn, mandate_id, *, actor, reason: str = "operator pause") -> Mandate
async def stop(conn, mandate_id, *, actor, close: bool) -> Mandate      # close=True queues reduce-only closes
async def finish_stop(conn, mandate_id) -> bool                          # STOPPING and flat -> STOPPED, locks released
async def release_locks(conn, mandate_id) -> int
```
`start`, in **one transaction** with `SELECT ... FOR UPDATE` on the mandate row:
1. `autotrade.enabled` must be 1 (`AUTOTRADE_DISABLED`), except the mandate's mode is ASK (level 1): ASK profiles
   may run with the master switch off (today's L1 behaviour is preserved).
2. `profile_errors(running=True)` empty (`PROFILE_INVALID` + codes).
3. TOTP when mode > ASK (`TOTP_REQUIRED`).
4. Capital: Σ `capital_budget_usd` of ACTIVE/PAUSED/STOPPING/HALTED mandates (excluding this one) + this budget ≤
   `max_allocated_pct`% of account equity (`paper_accounts.total_equity`, or the latest equity the API already uses)
   → else `CAPITAL_OVER_ALLOCATED` with `{allocated, budget, equity, cap_pct}`.
5. Insert one lock per `lock_keys(instruments)`; a unique violation → `COIN_LOCKED` with `{coin, holder_id,
   holder_name}` (look the holder up after the failed insert in a savepoint).
6. status ACTIVE; audit event (`ai_autonomy_events`, as today's transitions) and `record`-style audit row.
Idempotent: starting an ACTIVE mandate is a no-op success. From STOPPED/PAUSED/HALTED allowed (HALTED still needs
TOTP as RESUME does today).
`stop`: ACTIVE/PAUSED → STOPPING (locks kept); with `close=True` queue CLOSE_POSITION (reduce-only) for every open
position of the mandate's instance via the existing `flatten_instance` helper; immediately `finish_stop` if flat.
`pause` keeps locks. `release_locks` is called only by `finish_stop` and archive.

## H. Tests

- `tests/test_profile_lifecycle_api.py`: start/pause/stop/finish_stop matrix; two concurrent `start` calls on
  mandates sharing BTC (asyncio.gather on two connections) → exactly one ACTIVE, the other `COIN_LOCKED` naming the
  holder; capital over-allocation; master switch off blocks VETO/AUTO but not ASK; TOTP rules; machine token 403;
  STOPPING keeps the lock until positions are flat; `stop(close=True)` queues reduce-only closes.
- `tests/test_autonomy_advisory.py`: every transition rule in C, including HARD_STOP on a perp mandate succeeding
  against the real 050 CHECKs (the regression the old reset would have caused).
- Existing suites touching mandates/autonomy/brain cards stay green; any test that asserted the old ladder
  (promotion needs gate, demotion on breach, perps L1 only) is updated to the ADR 0011 rule **in the same commit**,
  each listed in the report with old → new expectation.
